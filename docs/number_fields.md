# Decomposition over number fields

The declared constants are part of a decomposition problem. Extending them can reveal intermediate fields that do not exist over QQ. This matters when comparing symbolic substitutions, studying symmetries, or deciding whether a component can be expressed using the coefficients available to an application.

Consider `f=x²+2/x²`. Over QQ it has one nontrivial two-map class, with inner function `x²`. Over `K=QQ(sqrt(2))`, two more classes appear, generated by `x+sqrt(2)/x` and `x-sqrt(2)/x`.

```python
import sympy as sp
from alggeom.decomposition.rational import search_rational

x, t = sp.symbols("x t")
f = x**2 + 2 / x**2
K = sp.QQ.algebraic_field(sp.sqrt(2))
over_qq = search_rational(f, x, parameter=t)
over_k = search_rational(f, x, parameter=t, constants=K)
assert over_qq.complete and over_qq.verify() and len(over_qq.decompositions) == 1
assert over_k.complete and over_k.verify() and len(over_k.decompositions) == 3
for sign in (-1, 1):
    h = x + sign * sp.sqrt(2) / x
    g = t**2 - sign * 2 * sp.sqrt(2)
    assert sp.cancel(g.subs(t, h) - f) == 0
```

These are three classes modulo fractional-linear changes of the intermediate coordinate, not three canonical printed formulas. The exhaustive claim is relative to `K`; it does not cover every further constant extension. The script [number_fields.py](../examples/number_fields.py) prints both searches.

## Exact constants and embeddings

Use exact SymPy algebraic numbers, with `QQ.algebraic_field(alpha)`. A field can be quadratic, cubic, or generated by a primitive element of a composite extension. Decimal approximations are rejected by the decomposition interfaces. For example, `sqrt(2)+sqrt(3)` generates the degree-four field containing both square roots.

```python
from alggeom.decomposition.rational import RationalDecomposition

for alpha in (sp.real_root(2, 3), sp.sqrt(2) + sp.sqrt(3)):
    constants = sp.QQ.algebraic_field(alpha)
    h = x**2 + alpha * x
    certificate = RationalDecomposition(h**2 + alpha, (x,), t, constants, t**2 + alpha, h)
    assert certificate.verify()
```

The chosen algebraic embedding is retained. For real graph checks it must be a real embedding; `sqrt(2)` and `-sqrt(2)` are valid exact real choices. A field declared through a nonreal generator is rejected by real verification, even if a particular expression happens to have rational coefficients. Number-field decomposition and real graph semantics are different layers.

## Quotients over rational function fields

The test corpus covers QQ, the quadratic fields generated by `sqrt(2)`, `sqrt(3)`, `sqrt(5)` and `sqrt(-3)`, the real cubic generator `real_root(2,3)`, and the composite generator `sqrt(2)+sqrt(3)`. It checks field-dependent rational classes, coordinates, automatic factor extensions, exact implicit resultants, and real embeddings where applicable.

Native coefficient conversion is shared through `algroots.domains`: whole algebraic coefficients are embedded before rational functions and matrices are built. This preserves `sqrt(-3)` in `QQ(sqrt(-3))(z)` even though its printed factors `sqrt(3)` and `I` separately lie outside the declared ground field. Quotient reduction, multiplication matrices, traces, norms, minimal polynomials and coefficient-generated fields use that conversion path.

```python
from algroots.quotient import QuotientAlgebra

z, a = sp.symbols("z a")
alpha = sp.sqrt(-3)
field = sp.QQ.algebraic_field(alpha).frac_field(z)
algebra = QuotientAlgebra.from_polynomials([a**2 - z - alpha], (a,), domain=field)
assert algebra.trace(a) == 0
assert sp.cancel(algebra.norm(a) + z + alpha) == 0
assert algebra.minimal_polynomial(a, t).all_coeffs() == [1, 0, -z - alpha]
assert algebra.normal_form(a * algebra.inverse(a)) == 1
```

The same path supports implicit reconstruction for the supplied relation `x²-z⁴-sqrt(-3)`. Regression tests exercise imaginary quadratic, real quadratic, cubic and composite number fields. These examples establish the tested operations and embeddings; they do not imply automatic constant-field extensions for every geometric problem.

The [coefficient-field tutorial](coefficient_fields.md) explains how the constant field `K`, the input field `K(z)` and the field generated by a factor's coefficients serve different purposes.
