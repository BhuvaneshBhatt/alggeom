# Specialization-aware Gröbner covers

## Why use this?

Computing a Gröbner basis over `QQ(a)` and substituting `a=0` can be wrong. For the ideal generated by `a*x` and `x+y`, the generic basis reduces to the point at the origin, while at `a=0` the fiber is the entire line `x+y=0`. A Gröbner cover associates a constructible condition with a basis that is valid throughout that condition.

```python
import sympy as sp
from alggeom.groebner_cover import comprehensive_groebner_cover

a, x, y = sp.symbols("a x y")
cover = comprehensive_groebner_cover((a * x, x + y), (x, y), (a,))
assert cover.verify_at((0,))
assert cover.verify_at((2,))
assert cover.specialize((0,)) == (x + y,)
```

## Construction and certification

The exact Buchberger procedure runs over the rational-function field of the parameters and records the leading coefficients and coefficient denominators used in the computation. On the principal open set where those expressions do not vanish, the sequence of polynomial reductions remains valid under specialization. The algorithm branches on each exceptional factor and recomputes the basis after imposing the corresponding parameter equation. Branches form a disjoint cover, and `specialize` selects the applicable basis. `verify_at` independently recomputes a Gröbner basis at the requested exact algebraic parameter values and checks equality of ideals.

The basis stored in a piece is a Gröbner basis, but is not required to be reduced or minimal. The `order` property records the lexicographic monomial order. An empty tuple represents the zero ideal; a basis containing `1` represents the unit ideal.

## Nested nonlinear parameter example

```python
import sympy as sp
from alggeom.groebner_cover import comprehensive_groebner_cover

a, b, x, y = sp.symbols("a b x y")
cover = comprehensive_groebner_cover(((a**2 + b**2) * x, a * y), (x, y), (a, b))
assert cover.verify_at((0, 0))
assert cover.verify_at((sp.I, 1))
assert cover.specialize((0, 0)) == ()
assert cover.specialize((sp.I, 1)) == (y,)
```

The divisor `a**2+b**2=0` splits into the algebraic graphs `a=I*b` and `a=-I*b`. Within each graph, the secondary exceptional condition `b=0` is resolved by another branch. This illustrates a supported recursive case, not a complete algorithm for arbitrary algebraic parameter varieties.

## Completeness boundary

`comprehensive_groebner_cover` currently completes for one-parameter systems when the exceptional algebraic roots can be represented exactly. For several parameters it handles exceptional hypersurfaces admitting rational linear specialization, including intersecting coordinate hyperplanes. It also recursively handles some nonlinear exceptional divisors whose defining polynomials split into *polynomial parameter graphs* over a finite algebraic extension of the constant field. A graph such as `a = I*b` is a regular algebraic chart; its intersections with other exceptional divisors are recomputed recursively. Graph intersections can produce additional (possibly empty) pieces, so piece counts are not stable mathematical invariants. The algorithm also computes a basis over the generic quotient function field of an irreducible nonlinear exceptional hypersurface if no further exceptional divisor appears. More general nested nonlinear parameter ideals, especially those with no finite polynomial-graph representation, raise `GroebnerCoverLimitError` instead of returning an incomplete cover. `max_pairs`, `max_pieces`, and `max_exceptional_degree` provide explicit resource bounds. Unrestricted comprehensive Gröbner systems on nested nonlinear parameter varieties still require a parameter-prime decomposition and repeated quotient-function-field specialization.

For general coupled polynomial systems, [exact fiber stratification](comprehensive_fibers.md) can still compute geometric dimension and bounded zero-dimensional cardinality through constructible elimination, without supplying Gröbner bases for each stratum.

## Mathematical references

The framework of comprehensive Gröbner systems is due to Weispfenning (1992), with branching and reduced-system algorithms developed by Montes (2002) and Kapur, Sun, and Wang (2013). See [mathematical references](references.md).

## Replaying exact certificates

`GroebnerCover.certificate()` constructs an explicit proof for each supported stratum. Each proof records identities expressing the basis in the specialized source generators, reductions of the source generators by the basis, S-polynomial reductions, and the parameter denominators that must remain nonzero. `GroebnerCoverProof.verify()` checks the identities and polynomial leading-term bounds and proves that the recorded constructible parameter conditions cover the parameter space without overlap. It does not rely on a finite set of test parameter values.

Certificate construction has additional computational requirements beyond generating a cover. If a branch does not admit the supported trace representation or the proof fails exact replay, certificate creation raises `CoverProofError`. A successful `verify_at(...)` comparison at particular values is a separate diagnostic, not a substitute for whole-stratum verification. For coupled nonlinear exceptions, use `verify_partition()` even when complete certificate creation is too expensive.
